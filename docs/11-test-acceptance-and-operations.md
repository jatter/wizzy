# 11 测试验收、上线门禁与运行手册

> 以下是待实现/待执行的测试计划，不是软件已通过测试的报告。现已有局部后端工程与真实隔离 PostgreSQL/Redis 自动化证据，见 [14 实施台账](plans/14-development-status.md)；不等于 T01～T29 整套验收，真实模型、正式客户端、备份和完整安全测试仍待执行。

## 1. 质量责任与证据

- 后端负责单元/真实 PostgreSQL 集成、RLS、并发、事件消费及供应商契约测试；前端负责组件/平台适配；QA 负责端到端、真机和发布证据。
- 教研双标并裁决 AI 金标准；AI 工程负责评测脚本和版本锁定；法务/产品负责上线适用性与授权，不让 QA 代签法律意见。
- 每项证据包含代码提交、环境、数据集/配置/价格版本、时间、执行人、结果、缺陷和复测链接。通过数量不能替代场景覆盖。
- PR 先写失败回归用例，再修复；测试应观察真实业务状态，不仅断言 mock 被调用。供应商 mock 用于注入超时/非法 JSON；发布前还要授权小流量真实契约测试。

### 日期与统计的固定回归样例

- 周窗口 `[2026-10-19T00:00:00+08:00, 2026-10-26T00:00:00+08:00)`；月窗口 `[2026-10-01T00:00:00+08:00, 2026-11-01T00:00:00+08:00)`。窗口起点包含、终点不包含，数据库先正确转换UTC。
- 10题输入：正确4/错误2/待确认2/未答1/不支持1；已判定原始正确率 `4/(4+2)=66.7%`，不是4/10，也不能不展示其余4题；订正后该原始提交指标不变，另外报告订正完成率。
- 2026-10-25首次确认错误，默认到期日10-26/10-28/11-01/11-08；若10-28失败，以10-28作为新D，避免旧未完成步并行累积。

## 4. 评测和性能执行协议

### AI 门禁

完整定义以 [04](04-ai-grading-and-evaluation.md) 为准：自动放行准确率点估计≥99%且单侧95%下限≥99%；误判正确率单侧95%上限≤1%；用学生/页簇稳健区间作保守判断。首批白名单覆盖目标≥60%，但安全优先。分层样本不足不能靠总体平均掩盖。每个发布候选留存脱敏错例、误差区间、覆盖率与实际费用。

### 压测口径

1. 固定数据集：清晰标准页、困难页、多页和不支持输入分开；明确平均图片大小、题数、网络、可用区和模型配额。
2. 持续30分钟基准与60分钟晚高峰模拟；10页同时任务是初始场景，不代表10页/秒。100在线不等于100同时付费AI调用；到达率阶梯增加至队列/预算限制，记录稳定吞吐。
3. 分别测 API 不含供应商的容量、使用模拟延迟的队列、授权真实供应商小流量。模拟供应商不能证明真实P95；配额不足时不伪造达标。
4. 同时报告P50/P95、队列等待、失败/待确认比例、最长任务年龄、供应商费用；不得通过丢弃困难任务优化P95。
5. 单页硬截止建议180秒；超时显示可重试/待确认。90秒是正常服务目标而不是把90秒后任务从统计中删掉。

## 5. 发布清单与可回退点

- 版本：数据库兼容迁移、API契约、前端构建、Worker、Prompt/规则/教材/价格配置均记录版本。
- 门禁：P0测试全通过，0个未处理的阻断/严重安全缺陷；AI/合规/删除恢复任一失败不放量。低优先级缺陷须书面接受并有到期时间。
- 灰度：授权试点影子 → 5% → 20% → 全量，每段至少覆盖一个晚高峰并满足样本要求；按家庭稳定分桶，不让同一份作业中途切模型。
- 回退：先关闭自动放行/新外呼，保留历史与上传状态；已过评测备选可接管，否则“OCR+家长核对”。应用回到前一兼容镜像，数据库不盲目down migration。
- 外部发布：小程序/App审核、教材授权、教育应用/生成式服务等必要手续均为独立条件；技术完成不能替代行政批准。

## 6. 监控、告警与日常责任

| 信号         | 初始告警阈值（可配置）                  | 接收/动作                   |
| ---------- | ---------------------------- | ----------------------- |
| API 5xx    | 5分钟>1%，且请求数≥100              | 值班后端；检查发布/DB，必要时回滚      |
| 模型外呼错误/429 | 5分钟>5%，且调用≥20                | AI/值班；限流熔断，不无界重试        |
| 队列等待       | oldest>60秒持续5分钟              | 运维；查配额/worker，不盲目扩容导致超支 |
| 质量         | 一例确认的高严重误判正确，或哨兵回归失败         | 教研/AI；立即关闭对应题型，复盘影响范围   |
| 成本         | 日/月预算80%；100%硬停止新付费步骤        | 负责人/运维；核查量、重试和版本        |
| 一致性        | outbox/报告stale>5分钟、未知账单超过约定期 | 后端/财务；幂等修复/人工对账         |
| 删除/授权      | 在线删除临近2工作日、授权到期、供应商回执超时      | 安全/运营；升级处置并如实告知         |
| 备份         | 最近恢复点>1h或最近备份校验失败            | 运维；立即处理，暂停发布            |

仅低流量百分比波动不自动触发事故级别，但内容泄露、越权和严重误判无需凑最小样本才处理。指标标签不放学生ID/题文，trace只保不透明操作ID；排查内容须受控工单。

- 每日：失败/死信、未知结算、预算、备份、供应商漂移哨兵检查。
- 每周：家长改判抽样、题型质量、复习积压、教材权利和临时访问权限巡检。
- 每月：隔离环境恢复演练、数据保留与删除抽查、供应商账单核对、成本路由评审。
- 可用性目标99.5%按完整自然月统计，30天月预算不可用时间216分钟；API和端到端AI分别呈现，供应商故障不能从用户端到端失败中删去。

## 7. 事故运行手册

| 事故             | 首步                    | 恢复与验证                                    |
| -------------- | --------------------- | ---------------------------------------- |
| 模型误判激增/版本漂移    | 关闭对应白名单自动放行；冻结配置扩量    | 锁定版本回归、评估已影响结果，标待复核而非静默改历史；教研批准再灰度       |
| 供应商超时/限额       | 限流熔断、保留任务和未知消费状态      | 查request_id/供应商账单；仅在确认安全和预算后重试，未验证备选不能顶替 |
| Worker/Redis宕机 | 保持DB任务为真源；停止重复调度      | 恢复租约扫描与outbox重放，核查外呼不确定区间和业务唯一键          |
| 数据越权/凭据泄露      | 立即撤销令牌/密钥与相关访问，保全最小审计 | 安全确定范围、履行法定报告/通知义务；修复后全矩阵回归，不删除证据掩盖事故    |
| 数据库损坏          | 切维护只读，停止写入和外呼         | 空环境恢复至核验点，重放墓碑/事件，对账后放流；RPO/RTO实录        |
| 成本突增           | 暂停新付费步骤，不删除用户历史       | 按路由/页/重试定位；修正额度和异常源，财务确认后恢复              |
| 教材授权到期         | 阻止新内容分发/生成，撤下过期片段     | 保留必要元数据和审计，更新学生绑定与预习；不能自动抓取其他版本补位        |

生产值班的姓名、电话、升级链、供应商工单方式必须在上线清单填写（不写入公开仓库）。试点发生阻断问题30分钟内响应为内部目标；对外服务承诺另签。每次事故48小时内形成无责复盘和可验证整改票据。

## 9. 受控消费者工程证据边界（2026-10-25）
