# 13 前端 UI 框架调研与商业化设计方案

> 决策日期：2026-10-25；落地范围更新：2026-10-26。适用范围：三端交互原型与后续前端实施。本文的“商业化设计”指界面与操作规范；上线仍须完成身份认证、真实业务接口、权限、安全与真机验收。

## 1. 选型建议

**平台端采用 Vue 3 + TypeScript + Vite + Element Plus；家庭端正式工程保持 uni-app（Vue 3 + TypeScript），当前 H5 原型使用 Vue 3 + Vant。** 管理台参考 Pure Admin 和 Vben Admin 的分区导航、筛选表格、详情抽屉、表单校验与权限呈现。只借鉴适合小知的模式，首版不引入完整后台脚手架及其无关模块。

孩子端以任务卡、清晰步骤、大触控区和鼓励反馈为主；家长端以待办、核对、学习趋势和家庭设置为主；平台端以高信息密度表格、审计证据和流程门禁为主。三端共享品牌和状态语义，不强制共享同一种页面布局。

## 3. 当前原型落地

源代码位于 `docs/prototype/ui`，使用 Vue 3.5.43、Element Plus 2.14.7、Vant 4.10.2、Lucide Vue 0.468.0；Vite 7.3.7 构建。依赖版本与 npm 锁文件已固定；这些是本次安装版本，不把每个包都宣称为最新版本。构建产物发布到 `docs/prototype`，无 CDN 运行依赖。

- 统一侧边栏、工作区标识、面包屑、角色入口、通知和帮助；小屏导航收起为遮罩菜单。
- 表格共用搜索、状态筛选、分页、固定操作列和空态；窄屏在表格内部滚动，页面不横向溢出。
- 表单具有必填/邮箱/业务规则校验，提交失败保留输入；详情用抽屉承载上下文。
- 模型目录显示版本、用途、得分、样本量、成本与状态；95.2% 示例明确为“未达准入”。评测报告单列分母、覆盖率、人工金标准和发布前置条件。
- 教材按授权与文件 → 模拟解析 → 源页映射/TXT → 提交抽检推进；不会把本地选择的 PDF 当成已真实识别。
- 家长核对保留机器原始记录，新增修订版本及依据；隐私操作演示二次验证和申请状态。
- 学校档案、名册校验、学生/家长元数据、后台账号邀请和权限申请均有交互入口。权限申请不等于实际权限生效。
- 现有24个业务页面（孩子7、家长8、平台9）：补齐设备配对/撤销、可关闭休息提醒、图片排序与真实canvas旋转裁剪、固定题块定位、检查中断同批重试、复习草稿续做、预习缺章/过期、工整度拒评和趋势排除、家长三级提示与独立完整讲解、多孩子切换清草稿及空态。
- 24页在1440/390px双视口检查48项，加18项业务流程，共66项通过。页面、字段、状态及接入边界见[交互交接](../prototype/INTERACTIONS.md)和[验证记录](../prototype/VERIFICATION.md)。

### 3.1 独立正式平台身份客户端已落地

2026-10-25 增量核对 [Pure Admin 官方仓库](https://github.com/pure-admin/vue-pure-admin) 与 [Vben 官方仓库](https://github.com/vbenjs/vue-vben-admin)：前者明确 Vue 3/Vite/Element Plus/TypeScript，后者当前 README 主述 Vue 3/Shadcn UI/Vite/TypeScript/monorepo。Vben 不应被简化为“只有 Element Plus 的模板”。本轮继续采用精简 Vue + Element Plus 工程，不整包复制模板；仅参考工作区导航和列表信息组织。

正式源码在 `frontend/platform`，已接通0015身份七接口、0018模型目录登记/修订五接口及0021账号详情/历史/变更/独立审批五接口。采用 Vue 3.5.43、Element Plus 2.14.7、TypeScript 5.9.3、Vite 7.3.7，显式按需导入组件及对应样式（参见 [Element Plus 官方快速开始](https://element-plus.org/en-US/guide/quickstart.html)），不全量注册。2026-10-26生产构建结果：JS **379.80 kB / gzip 133.14 kB**，CSS **98.41 kB / gzip 15.30 kB**，HTML **0.45 kB / gzip 0.32 kB**；只是当前切片体积，不代表未来全平台性能预算。

正式身份工作区采用青绿 `#177b65` / 墨绿 `#173d35`，与下面演示原型的蓝色/深蓝导航**并不相同**。布局模式和状态语义延续原型，但品牌色、密度与正式三端 token 尚须统一设计评审，不能宣称已经品牌全量统一。桌面与390px视觉证据及其模拟数据边界见 [截图说明](../evidence/platform-web-2026-10-25/README.md)。

依赖核验：官方 npm registry 审计发现正式客户端原 Vite 7.2.2 命中高危公告 [GHSA-rq7h-c2jc-7f22](https://github.com/vitejs/vite/security/advisories/GHSA-rq7h-c2jc-7f22)，已按 [官方7.3.7补丁](https://github.com/vitejs/vite/releases/tag/v7.3.7) 升级锁文件并重跑构建/测试。升级后本客户端 `npm audit --registry=https://registry.npmjs.org` 为0个已知漏洞，证据在 [审计JSON](../evidence/platform-web-2026-10-25/npm-audit.json)。同日也将 `docs/prototype/ui` 独立升级至Vite7.3.7，重新构建并通过45项浏览器回归，官方registry审计同为0个已知漏洞，详见[原型独立证据](../evidence/prototype-ui-2026-10-25/README.md)。两份审计仅覆盖各自锁文件，不是源码审计或生产安全认证；即使补丁已升级，也不向非可信网络开放开发/预览服务器。未执行 `npm audit fix --force` 或大版本批量替换。

## 4. 三端演示原型设计规范（正式身份工作区差异见3.1）

| 项目 | 基准 | 使用规则 |
|---|---|---|
| 品牌主色 | `#4266df` | 主按钮、活动导航、可操作链接；避免满屏强色 |
| 导航 / 背景 | `#18243e` / `#f5f7fb` | 深色工作区导航，浅色业务内容区 |
| 内容层级 | 页面标题 → 区域标题 → 关键指标 → 辅助说明 | 不能只通过字号或颜色表达状态；标签配文字 |
| 字体 | 系统中文无衬线字体栈 | 正文可读，辅助字有对比；不加载远程字体 |
| 间距与圆角 | 4 / 8px 节奏，卡片适度圆角 | 表单、表格、抽屉保持一致，不堆砌装饰 |
| 图标 | Lucide 线性图标 | 导航和按钮有文本；纯图标按钮提供可访问名称 |
| 儿童触控 | 主要操作目标至少 44px，原型按钮基准 46px | 一屏一个清晰主任务，不靠手势发现关键功能 |
| 响应式 | 1200px 内容收缩、800px 移动布局 | 390px 与 1440px 做路由回归；正式交付增加平板和真机 |
| 状态 | 加载、成功、失败、待确认、空态、禁用 | 待确认不是答错；拒绝准入、未授权需显示原因 |
| 动效 | 短过渡，支持减少动态效果 | 不用模拟动画宣称真实 AI 处理进度 |

组件职责：PageHead 统一标题/说明/操作；DataGrid 统一数据列表；FormDialog 统一表单与保留错误输入；TrendChart 当前为固定演示 SVG。不要让页面自行定义另一套相同组件。

## 5. 正式开发与跨端边界

1. 平台正式工程 `frontend/platform` 已使用 TypeScript、Element Plus 按需组件/样式与真实API，覆盖独立身份、0018模型目录读写、0021账号角色/启停/独立审批、0022学校目录、0023学校组织/年级/班级及0024校内学生名册/逐学年在读关系；0026–0028另已接教材隔离存储、内嵌文本提取、人工逐页校核、独立抽检发布/撤回、章节与PDF物理页映射、授权原PDF单页并排校核；扫描图片OCR、公式表格结构化和AI索引/检索仍缺。名册批量导入、监护关联、模型评分及账号邀请/MFA管理继续按同一规范逐页接入，不把演示原型自动算作正式实现。
2. 家庭正式工程 `frontend/family` 已使用 uni-app / Vue 3 / TypeScript、原生 uni 组件与轻量设计令牌，首个切片通过 H5/微信小程序构建和真实 API 浏览器验收，详见[家庭客户端计划](../plans/2026-10-26-family-client.md)。**Vant Web 不能直接视为 uni-app / 微信小程序兼容组件**，Vant Weapp 也是不同组件实现。已验证按钮/表单的构建及 H5 语义，H5图片选择、排序、旋转裁剪、真实上传和幂等重试已通过浏览器联调；相机权限与微信图片编辑继续真机验收。
3. 原型中的角色切换仅用于查看页面；正式登录、家庭切换、MFA、设备绑定和会话撤销必须走服务端。菜单隐藏不能作为授权。
4. 生产数据必须增加加载/空/失败/409冲突/权限撤销状态；长表格服务端分页，筛选绑定查询参数，异步任务使用后端真实状态。
5. 本地登记模型不做连接测试；生产模型管理通过服务端凭据引用接入供应商，禁止前端保存密钥。家长改判仅进入候选样本池，双人标注后才可成为评测金标准。
6. 数据库继续使用 PostgreSQL；UI 框架选择不改变数据模型。原型没有连接后端；独立正式后端迁移head为`0028_textbook_content`，平台身份客户端已接RBAC、模型目录登记/修订、账号角色/启停/独立审批、学校目录、按学年组织树及校内学生名册，家庭客户端已接授权/复习、图片上传和作业历史筛选切片，教材已接0026–0028限定范围（见本节第1项），真实模型评分和完整账号权限治理仍未完成，详见 [数据模型](../architecture/06-data-model-and-api.md) 与 [正式工程台账](../plans/14-development-status.md)。

## 6. 实施与验收建议

在现有 FE1/FE2 计划中安排，不以增加框架替代业务实现：第 1–2 周确认设计 token、跨端能力和最小后台壳；第 3–6 周完成业务列表/详情/表单与 API；第 7–10 周完成模型、教材与权限状态机及异常态；第 11–12 周进行真实设备、无障碍、安全和受控试点验收。学校等 P1 功能独立排期。

交付门槛：需求 ID 有页面/操作/字段/权限/异常/测试映射；关键操作无死按钮；输入失败不丢失；空数据不伪造趋势；移动端无页面横向溢出；表格、弹层键盘可达；灰度/回滚和敏感操作有独立审批证据。当前自动化覆盖见 [原型验证记录](../prototype/VERIFICATION.md)，真实服务和真机测试另行验收。

原型不是全量SRS完成证明。当前原型仍缺真实相机权限、服务端OCR坐标题框、断网持久恢复、认证/RBAC执行、真实OCR/PDF解析、模型调用/发布、服务端教材发布及删除/导出、跨端真机验证。原型已可真实裁剪/排序本地图片并定位固定示例题块，但题块不来自所选照片；TXT仍为固定样例。独立正式工程的0026–0028教材实现与原型分开验收。
