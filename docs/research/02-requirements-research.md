# 02 GitHub 与官方产品需求调研

> 核验日期：2026-10-25。研究方式：检索及阅读项目原始 README、官方产品/API 文档；没有运行项目。完整地址和边界见 [来源清单](sources.md)。本章不是市场份额或准确率排名。

## 1. 参考项目与可借鉴内容

| 来源 | 已观察到的能力/定位 | 转化为小知需求 | 使用限制 |
|---|---|---|---|
| S01 margrop/wrong-notebook | 拍照/输入、知识标签、变式、打印组卷、掌握跟踪；页面声明 MIT | FR-C03、FR-M01～05、FR-P03～05；打印后也要回填作答 | 不等于有家庭隔离/儿童授权；不复制共享演示账号做法 |
| S02 Liangbiaoyong/MistakeBook | 截图转结构化笔记、错因筛选、去重、复习时先隐藏答案 | FR-M02/M04、FR-C05；低打断录入和可纠正 OCR | 原项目是个人考试桌面工具；未核实许可，不复制代码；自评置信度不照搬 |
| S03 PaddlePaddle/PaddleOCR | OCR 与文档结构化、坐标/公式等工具；Apache-2.0 | FR-C04、AI-01、AI-02；保留框选定位和原文 | 文档解析榜单成绩不能外推为小学生手写判题准确率 |
| S04 open-spaced-repetition/fsrs4anki | 间隔重复调度项目 | FR-M04；记录每次真实复习结果与时间 | 首版先用透明固定间隔；FSRS 待数据与许可审核后引入，不承诺学习效果 |
| S05 ankitects/anki | 间隔重复卡片学习 | 题目与答案分面、先自测再反馈 | 只借鉴交互思想，不复制其代码/素材 |
| S06 openwebwork/webwork2 | 面向课程的在线作业系统 | 题目版本、提交/重试、评分与课程内容分离 | 不是拍照手写批改方案；课程制不直接照搬家庭制 |
| S07 dcloudio/uni-app / 官方文档 | Vue 生态、多平台编译与专有能力适配 | NFR-PORT-01；统一类型与平台适配层 | 摄像头、打印、通知、登录等仍逐平台验证 |

下表“转化为小知需求”包含设计推导，不表示每个原项目逐项具备对应能力。

结论：从独立错题本借鉴“小步录入—核对—复习—回填”，从文档 OCR 借鉴“结构化与坐标”，从课程系统借鉴“版本化作业”。小知仍需自建亲子权限、质量评测、多租户、教材授权和运营能力。[S01–S07]

| S10 阿里云视觉理解 | 多图输入、视觉问答与定位类任务 | 用于图文结构化和困难题复核，但题型准确率必须自测 |
| S11 阿里云价格 | 存在 OCR、VL、Flash、Max 不同价格层 | 将 OCR、解释、判题、复核分工，价格口径见 `09` |

| S14 火山官方模型价格入口 | 入口需 JavaScript；本次只取得需启用JavaScript的页面壳，未取得价格表 | 保留豆包候选；没有可复核价格表，不填写精确单价或宣布最便宜 |

专用批改服务可能减少自建工作，也可能存在题型、配额、数据保留和合同限制。先做“自建流水线 vs 专项 API”的同集评测；不是预先认定自建一定更准或更省。[S08–S14]

## 3. 需求推导矩阵

| 场景/痛点 | 需求 | 阶段 | 可验证结果 |
|---|---|---|---|
| 一页多题、错位、涂改 | 分题切图、题干/答案区分、原图高亮、人工修正 | P0 | 一道题坐标和题号能回到原图 |
| OCR 看错数字导致错判 | 原始文本/修正文分开；重跑派生结果 | P0 | 修正后错题和报告可一致更新 |
| 上传同一页反复扣费 | 幂等上传/创建任务；相同作业版本复用 | P0 | 重试创建不重复计入产品额度 |
| 错题越存越多 | 去重建议、按知识点筛选、到期复习、掌握重开 | P0 | 重做成功不会删除历史，复错重新到期 |
| 每周/月机械整理 | 结构化报告 + 一键生成复习计划 | P0 | 报告题数与源记录一致、空周期不编造 |
| 纸面复习没反馈 | 练习卷题号映射、照片/手动回填 | P1 | 能追踪复习题是哪道历史错题 |
| 家长不会辅导 | 先问思路、逐级提示、常见误区、答案受控 | P0 基础/P1 会话 | 孩子首次提示不直接给最终答案 |
| 写字与拍照混为一谈 | 图片质量与工整度分开、样本不足不评分 | P1 | 模糊图片提示重拍而不是低书写分 |
| 预习脱离明天课程 | 课表实例 → 教材章节 → 预习清单 | P0 | 调课后仅重建受影响日期预习 |
| 多家庭混用 | 家庭租户、儿童绑定、文件和任务隔离 | P0 | 任何猜测 ID/文件 key 不可越权 |
| 模型过度自信 | 待确认状态、证据、纠错、分题评测 | P0 | 冲突不自动判正确、不计掌握 |
| 教材版本不一致 | 年级/上下册/版次/章节/页码管理 | P0 | 同名课文不同版次不混淆 |

“痛点”是对上述功能与目标用户场景的产品推断，并非已开展用户访谈后的统计结论。试点需访谈至少 10 位家长、5～10 位儿童（取得监护人同意），观察上传、核对、订正与预习，不只问是否喜欢 AI。

## 4. 不照搬的能力

- 不采用示例项目开放共享账号、全局可见图片或用户自填模型密钥的消费端模式。
- 不采用“模型输出一个分数就是最终结论”的判题设计。
- 不在首版生成任意 SVG/HTML/脚本动画；模型文本不能作为可执行内容渲染。
- 不采集其他产品的题库/教材，也不将开源代码许可当成教材使用授权。
- 不用 GitHub star、供应商广告准确率或通用数学基准代替小知真实作业测试。
