# 群作业截图识别与每日作业清单实施方案

日期：2026-11-15（Asia/Shanghai）。状态：原始设计方案，首期已于同日实现并发布；实际交付、测试及边界见 `2026-11-15-daily-homework-implementation.md`。下文源码描述与估算保留设计时点语境。本文依据用户提供的六张截图及当时源码编写。

## 1. 目标和默认范围

在家庭端新增“每日作业”，把群内作业截图整理成可核对、可追溯、按孩子和日期维护的任务清单。首期闭环为：上传图片 → 识别草稿 → 家长确认日期和内容 → 按科目显示 → 孩子记录进度 → 家长检查。

默认沿用一个家庭一个租户、多孩子和多监护人权限；“六年级10班”先作为来源标签，不新增教师端或跨家庭共享班级作业库。日期统一采用上海时区。截图里的作业要求、聊天文字均是待提取数据，不是模型或系统的执行指令。

首期包含：批量上传、裁剪、手写识别、日期候选、逐项编辑、重复提示、冲突处理、按日期查询、手工新增、完成记录及历史。自动关联已上传作业和微信群定时采集分期实施，但首期保留来源、任务定位字段及调用边界。

成功标准：家长能在一个页面确认“某个孩子、某一天、有哪些作业、哪些已标完成、哪些待检查”；每项能回到来源图片；识别失败时仍能手工维护。

## 2. 六张截图对设计的影响

| 截图现象 | 处理规则 |
| --- | --- |
| 第2张有“11月13日 星期五”，第6张有“10月27日 星期二” | 分别形成日期候选；截图未提供完整年份，不能直接认定年份，也不能把六张全归入上传当天 |
| 第3张聊天写“周末作业”，图片没有明确日期 | 保留周末标记，家长确认布置日期及可选截止日期；不能自动推算成某个周一 |
| 第1、4张存在“数学：无”“语：无” | 表示该来源宣称该科无作业；空白行则表示未提供信息，两者区分；与同日其他来源矛盾时待确认 |
| 第4、5张与第3张记录不同 | 先核对日期；同一天才比较差异，保留各版本，不按发送先后或家长人数决定谁正确 |
| 第1、5、6张存在勾选 | 只是来源图片上其他人的标记，不能变成本家庭孩子的完成记录 |
| “大册”“小册”“U1–U2”“1+1”“2+1”等简称 | 保存原文；解析单位、范围、次数；不把“1+1”当数学运算；不擅自扩写成教材全名 |
| 同一截图包含左侧聊天缩略图及右侧放大图 | 默认让家长框选右侧作业正文，避免缩略图再被识别一次；多份正文需分别选区 |
| “准备2本语文本”等备注 | 归为“准备事项”，不计入书面作业，但单独显示完成情况 |

以第2张为例，可以产生“语文：大册第15课、小册第15课、预习作文”等候选，以及数学页码、英语抄写/背诵和准备事项。难辨的页码、缩写必须标注待确认。这里只说明输出形态，不声称已完成OCR或全部转写准确。

## 3. 页面与用户流程

家庭端学习空间增加“每日作业”，与现有“拍作业”“作业记录”并列；学习首页展示当天摘要和历史未标完成项。家长中心提供导入、内容修改和核对入口。首期不改变现有登录后默认落点。

1. **选择孩子并导入**：选择1–10张图片，每张≤10 MiB，沿用现有上传限制；可裁剪、旋转、移除。可先填目标日期，也可暂不填。
2. **识别中**：后台处理，页面显示逐图状态；退出后能从导入记录继续。单图失败不丢弃其他图的草稿。
3. **核对草稿**：桌面左图右表，手机上下显示；逐项显示学科、原文、规范化内容、日期候选和疑点。点击条目定位原图区域；自动坐标只是辅助，允许人工调整。
4. **确认入清单**：家长确认完整日期、任务内容、重复/冲突处理后发布；可拆分多天保存。允许先保存已核对部分，但明确显示“清单待补充”，未处理部分留在草稿。
5. **每日查看**：日期切换、学科分组、进度筛选；任务支持“开始”“标记做完”“请家长检查”“重新打开”。家长可修改任务、核对完成、标记免做并填写原因。
6. **后补信息**：同一天再次上传，展示新增、重复、差异三类候选；只追加或经确认修订，不替换整天清单。修改已完成任务的页码/范围时，清除当前核验并提示重新检查，保留旧历史。

页面摘要建议：“11月13日 · 已标完成3/7项 · 待家长检查2项 · 清单待补充”。这是界面样例，数值不是对截图的识别结论。

日期需区分 `assigned_date`（布置日期）、`due_at`（可选截止时间）、`message_sent_at`（来源消息时间）和 `uploaded_at`（入系统时间）。上传时间和消息时间都不能直接替代布置日期。若图片与用户所选日期不一致，必须展示冲突后确认；“今天/明天”只在来源消息时间可靠时解析，否则待确认。

## 4. 完成和核验规则

| 字段 | 建议值 | 含义 |
| --- | --- | --- |
| `work_state` | `pending / in_progress / submitted / completed / exempted` | 未标完成、进行中、已提交待检查、已标完成、免做 |
| `verification_state` | `unverified / guardian_confirmed` | 是否有当前版本的家长核验 |
| `completion_actor` | `child / guardian` | 谁标记完成；自动模型首期不能写完成状态 |
| `item_type` | `written / recitation / reading / preview / preparation / other` | 书写、背诵、阅读、预习、准备、其他 |

“未标完成”只表示系统没有完成记录；家长明确检查后才能说“确认未完成”。“已标完成”与“家长已核验”分开展示。背诵、阅读等不能只凭一张书面照片确认完成。完成不等于做对，有错误的作业可以已写完，订正任务另计。

来源图片上的勾选只记录为 `source_mark`，不影响以上字段。现有 `submissions.status=completed` 表示处理任务结束，也不能直接写成清单已完成。

统计按确认后的任务条数计算，不把总数7条说成7道题；免做条目不进入应做分母，准备事项另计。当天有待处理草稿、日期冲突或未核对科目时显示“清单待补充”；0条且未核对显示“未录入”，全部确认无作业显示“今日无作业”，二者都不显示100%完成。只有完整确认、无待处理来源、全部应做项已完成且均经家长核验，才显示“今日作业已核对完成”。

历史未完成任务仍属于原布置日期，在今天显示“待补”入口，不复制新任务。截止时间未填写时不标“逾期”；周末任务不会每天重复生成。

## 5. 识别技术与现有工程接入

当前源码中已存在可复用部分：

| 当前模块 | 接入方法及限制 |
| --- | --- |
| `frontend/family`：uni-app、Vue 3、TypeScript | 新增 `DailyHomeworkPanel.vue`、`HomeworkImportPanel.vue` 及清单API类型；复用选图/裁剪和学生切换机制 |
| `backend/src/wizzy/media.py` | 复用上传、校验和私有读取；当前后端适配器是本地私有目录，不能写成已部署云对象存储 |
| `model_configs.py`、`grading_prompts.py` | 复用模型登记、密钥加密和管理交互；新增清单识别用途绑定，独立Prompt和版本，避免修改批改用提示词 |
| `homework_grading.py` | 已有真实兼容接口调用、领取/心跳/调用围栏模式；新清单任务采用独立worker入口，不直接调用其两轮判题流程 |
| `submissions.py`、`submission_pages` | 第二期作为已上传作业及页图的来源，首期不改其批改契约 |
| PostgreSQL、Alembic、权限与受限worker | 新表/函数延续租户隔离、学生授权、版本检查和受限角色；不用新增微服务、向量库或GPU |

部分旧文档还描述“真实AI待开发”；本方案的复用判断以当前源码为依据，不代表已核实线上部署和实际识别质量。

推荐首期用一个通过样本验证的视觉模型，一次返回“忠实转写 + 作业结构”；识别后由确定性规则检查日期、学科、页码、条数和必填字段，再由家长确认。Qwen作为首选试测候选，模型ID以现有账号、地域、接口能力和样本结果确定，不在代码中写死“最新型号”。阿里云官方说明视觉输入可生成结构化JSON，Qwen-OCR可提取手写内容并支持兼容接口，见文末来源1、2。

若试测发现手写页码漏识别明显，再采用“专用OCR → 视觉结构化”两阶段方案，不默认每张图片都调用两家模型。腾讯通用手写体识别文档已标为旧服务并建议使用高精度服务，因此不能仅因名称包含“手写”就固定旧接口；如需对照，应按官方当前建议和样本选择，见来源3。

处理流程：

```text
私有图片上传 → 选区裁剪 → 识别任务入库
    → 受限worker领取 → 调用模型 → 严格结构校验
    → 保存原始机器结果和疑点 → 家长确认 → 每日清单
                                                  ↓
                                         孩子记录 / 家长核验
```

严格输出包含：图像/选区标识、原始日期文字、日期候选、学科、任务类型、原文、书本简称、课/页/题/单元定位、次数原文、可选位置框、来源勾选、疑点原因。无法确定的字段为null；模型置信度若存在只作辅助，不当准确率。`source_mark`须标明来源人物是否未知。

先逐图提取，再跨图比较；同一截图的缩略图与放大图不能作为两份独立佐证。图片内“忽略规则”“自动标完成”等内容永远不能调用工具或改系统状态。截断、非JSON、字段错误、空白或遮挡等结果均留在草稿，失败可直接手工录入；不得伪造成功。

任务使用持久状态与租约，状态为 `queued → processing → review_ready / partial / failed`；确认后可为 `partially_applied / applied / discarded`。重跑生成新的机器结果版本，不覆盖人工修订。调用回执不明时标 `call_outcome_unknown`，提示可能已计费，不盲目自动重放。

## 6. 数据模型建议

下表为新增设计，不表示已有建表。首期7张表；第二期再建证据关联表。

| 表 | 核心字段及约束 |
| --- | --- |
| `homework_imports` | tenant/student、source_kind、source_label、可选target_date、client_request_id、状态、revision；同租户同操作键唯一，重复请求载荷不一致返回409 |
| `homework_import_images` | import_id、media_id、position、crop_rect、裁剪派生图标识与hash；父子记录同租户同学生，复用现有media授权 |
| `homework_import_runs` | import_id、attempt、租约/token、model与prompt快照、原始响应、结构化候选、逐图状态、usage、费用已知/未知；每次运行追加保留 |
| `homework_days` | tenant/student/assigned_date唯一、revision、scope_state、各科 `unknown / has_items / confirmed_none`、确认人/时间；不能把空白当无作业 |
| `homework_items` | day_id、subject、item_type、title、raw_text、locator JSON、due_at、work_state、verification_state、revision、sort_order；语义字段修改触发重新核验 |
| `homework_item_sources` | item_id、image_id、run_id、候选条目标识、原文快照、可选bbox；支持一项多来源；约束来源与任务同租户同学生 |
| `homework_item_events` | item_id、actor、action、修改前后快照、reason、client_request_id、created_at；追加保存编辑/完成/重开/核验/免做历史 |

`locator`首期按JSON存储明确的 `book_alias / book_id / lesson / pages / units / question_range / repetition_raw`，其中book_id允许null。家长首次可把“大册”映射到孩子当前学期某本练习册，映射暂存家庭设置且保留原文；未经确认不自动套用到其他学科或孩子。不开发通用别名管理平台。

机器草稿与正式任务分开；确认操作事务内校验全部相关版本，原子写入清单/来源/历史并标记候选已应用。手工任务的来源类型为manual，无需伪造图片。重复候选可显式指向现有item，多次确认同一候选不得新增重复任务。

索引至少包含 `(tenant_id, student_id, assigned_date)`、`(day_id, subject, sort_order)`、`(item_id, created_at)`、识别队列状态与领取时间。外键或受限函数校验同租户同学生关联，不能只依赖前端传入ID。原始响应和衍生图片随授权撤回/删除流程处理，不让审计无限保留图片正文；日志不输出群聊原文和图片。

## 7. 首期API契约

所有路径相对 `/api/v1`，仍使用现有认证和响应封装。写操作使用 `client_request_id` 幂等；修订使用 `expected_revision`，冲突409。孩子只能查看本人及记录本人进度；导入、内容发布和家长核验为监护人权限。

| 接口 | 用途 |
| --- | --- |
| 现有 `/media/upload-intents`、`/{id}/upload`、`/{id}/complete` | 图片接收，不新增公开图片地址 |
| `POST /homework-imports` | 创建识别任务：student_id、可选target_date、source_kind=manual_image、source_label、media_ids与选区 |
| `GET /homework-imports?student_id=...&cursor=...` | 恢复导入记录，状态和分页 |
| `GET /homework-imports/{id}` | 查看逐图状态、最新草稿、历史结果版本及疑点 |
| `POST /homework-imports/{id}/retry` | 显式重试指定失败图，保留原结果并记录新调用；未知外呼结果先提示风险 |
| `PUT /homework-imports/{id}/draft` | 保存家长修改、日期选择、候选合并/排除及科目无作业声明 |
| `POST /homework-imports/{id}/apply` | 将明确选中的候选原子写入对应日期；传入草稿和目标日期清单版本及冲突决策 |
| `GET /students/{id}/homework-days?from=...&to=...` | 日期摘要，建议单次最多31天 |
| `GET /students/{id}/homework-days/{date}` | 按科目返回任务、核验状态、清单完整性及待补来源 |
| `POST /students/{id}/homework-days/{date}/items` | 手工新增，图片识别不可用时仍能使用 |
| `PUT /homework-items/{id}` | 修改内容、截止时间、免做或软删除，记录原因及版本 |
| `POST /homework-items/{id}/progress` | 开始/提交检查/完成/重开；服务端校验操作者可执行动作 |
| `POST /homework-items/{id}/verify` | 家长确认完成或确认仍未完成，不直接信任前端角色标识 |
| `PUT /students/{id}/homework-days/{date}/scope` | 家长确认各科覆盖和清单完整性；有未处理冲突时拒绝标为完整 |

精确图片hash只在家庭/孩子授权范围内用于重复提示。重复上传不直接拒绝：同一页可能确为不同日期的作业，家长可明确“用于另一天”。近似文本仅提示可能重复，不自动删除。“大册2页”和“大册P2”分别可能是数量和页号，不能直接合并；词相近但范围不同只能提出冲突候选。

## 8. 后续自动关联作业的预留

首期即保留稳定item_id、locator、来源证据和版本。第二期增加 `homework_evidence_links`，支持一个任务对应多份提交、多页图片，也支持一页图片对应多个任务；关联到现有submission_id/media_id，可记录局部bbox和覆盖范围，不能只在提交表放单个task_id。

内部边界建议为：

```text
HomeworkSourceAdapter.normalize(input) -> SourceEnvelope
AssignmentExtractor.extract(images_or_text, context) -> Draft
HomeworkMatcher.propose(student_id, item_revision, submission_id) -> MatchCandidates
CompletionEvaluator.evaluate(item_revision, evidence_links) -> CompletionProposal
```

这些是职责边界，首期只实现manual_image路径，不创建空插件框架。预留的公开契约（第二期再开放路由）为 `POST /homework-items/{id}/evidence` 和 `POST /homework-match-jobs`，结果保存为候选，必须含证据、缺失范围、算法版本和来源版本。

匹配先按孩子、学科、日期候选范围、书本/课/页/单元筛选，再用视觉对照可见内容，不以关键词相似就认定完成。家长可手动选择历史日期，支持补交、跨日、一次交多项。任务修改或证据撤回后候选失效，必须重新评估。

输出区分：未找到证据、疑似匹配、部分覆盖、覆盖充分待确认、无法判断。没有上传证据不等于没有做；照片中一页有答案不等于两页全部完成；背诵和预习等需家长确认或后续新增适合的证据类型。首个匹配版本仍只建议状态，验证充分后再讨论有限自动确认。

## 9. 后续微信群消息与定时任务预留

消息入口与识别服务分开。未来来源统一输出 `SourceEnvelope`，字段包含 source_kind、connector_id、source_message_id、conversation_ref、可选sender_ref、sent_at、received_at、text、media_refs、source_revision、relation（新增/更正/撤回）。外部身份须经服务端映射到授权家庭/学生，不接收调用者任意指定其他学生。

幂等按连接器、会话和消息ID处理，同消息的新修订仍可进入更正流程；没有可靠消息ID时只做内容hash去重候选。群消息中的文字作业直接走结构化提取，图片才走OCR；引用、补充、更正、撤回先保留关联，再提示家长修订正式清单，不抹掉已确认记录。

未来业务接口可为 `POST /homework-source-events`，只向专用连接器开放；定时计划保存timezone、run_at_local、lookback_window、cursor和enabled。采集采用游标及重叠窗口，避免某个时间点后发的作业遗漏；当天晚到信息仍能追加，更正触发待核对提示。失败不推进游标，重跑靠消息幂等避免重复。

**本次未验证到可直接读取截图中个人微信群消息的官方接入条件，不能承诺定时抓取已具备可用接口。** 普通微信群来源与企业微信来源必须分别验证账号类型、权限、可获取的数据和运行环境；未验证前，以人工上传/复制群消息为可用入口。届时采集方式单独立项验证，业务清单和识别接口无需重做。本次不创建定时任务。

## 10. 实施批次、验收与费用

以下为在现有工程上新增功能的估算，按1后端+1前端、共享QA、模型账号可用计算；不含微信消息接入和生产发布审批，不是交付承诺。

| 批次 | 工作与交付 | 估算 |
| --- | --- | --- |
| A：手动清单 | 建表迁移、权限、按日维护、手工新增、进度/核验历史；识别暂未可用也可使用 | 3–4工作日 |
| B：图片识别闭环 | 选区、独立识别worker、严格输出、草稿核对、去重/冲突、幂等确认、模型用途绑定 | 4–6工作日 |
| C：样本与集成验收 | 真实手写图评测、异常/隔离/并发测试、H5和小程序关键链路 | 2–3工作日 |
| D：证据匹配 | 关联现有提交、范围覆盖、候选解释和家长确认 | 另估4–6工作日 |

A–C建议预算约2–3周。微信定时来源待接入验证后另估。可以先交付A，再逐步打开B。

必须验证的场景：

1. 六张图的日期候选不被强制合并；缺年份、无日期、周末和图片/用户日期冲突都需确认。
2. 放大图与聊天缩略图不产生重复任务；多图同项保留多个来源但只生成一项。
3. “无”与空白不同；同日“无”和具体任务冲突不能静默覆盖。
4. 来源图上的勾不影响本家庭孩子；已标完成、家长核验、批改结束含义不混用。
5. “P13/P14”可拆定位，“2页”不自动认定P2，“1+1/U1”不能误转写而无提示。
6. 单图失败、超时、截断JSON、断网、重复提交、重复回执、worker旧租约和未知调用费用不丢草稿、不重复建任务。
7. 家长同时修改返回409；切换孩子/退出后不展示旧结果；越权家庭/学生/图片/候选关联被拒绝。
8. 完成项改范围会待重新核验；部分上传显示清单待补充；0条不显示100%；截止未知不标逾期。
9. 撤回授权后停止领取/外呼/保存/读取，并按现有删除流程处理衍生结果；平台普通运维不能浏览家庭群图片。
10. 第二期匹配验证一图多任务、多图一任务、少交一页、背诵无照片、日期补交、任务修订使候选过期。

六张图适合作为首批回归用例，不能证明识别准确率。另收集经允许处理的30–50张不同手写样本，两人核对日期、科目、任务边界、页码/单元；区分调参样本和未见过的验收样本。报告条目召回率、误新增率、关键定位字段准确率、整页无需修改比例及人工修改耗时；不以模型自报分数替代这些指标。

建议试点目标：清晰样本条目召回率≥95%、误新增率≤2%、关键定位字段准确率≥95%；所有规则性阻断用例100%通过。以上是待验证目标，不是当前能力。识别延迟可先以单张P95≤30秒为目标，超时异步等待或手工录入；在真实账号实测后再定超时和批量上限。

费用按实际调用记账：月费用 = 识别图片调用费 + 必要复识别费 + 第二期匹配费 + 存储。JSON无效等失败调用也可能收费，usage缺失记“费用未知”。每批保存调用次数/模型/usage和费用状态，按家庭设置上限；首期不默认调用现有两轮批改流程，不在没有账号地域、实际token和账单之前承诺固定每张价格。

开发完成时执行：后端相关单元与隔离PostgreSQL集成、家庭端类型检查/单元测试/H5与小程序构建、真实浏览器“上传→草稿→确认→进度→核验→刷新恢复”链路，以及经授权的真实模型样本验证。方案文档检查不等于以上功能验收通过。
