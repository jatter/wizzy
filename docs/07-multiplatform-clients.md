# 07 多端前端与三端交互方案

## 1. 工程和交付边界

**建议：uni-app（Vue3/TypeScript）一套家庭端工程，明确孩子/家长两个导航与权限上下文；平台管理端独立 Vue3 Web。** 不将 WebView 包装说成完全原生能力。uni-app 编译到多平台仍需平台条件代码及差异验证。[S07](research/sources.md)

- 家庭端模块：auth、child、parent、shared-components、api-client、platform-adapters。只有确有平台差异的摄像头/存储/登录等才放 adapters，不造跨所有 UI 的抽象框架。
- 家长入口需监护人认证；孩子入口需家长绑定设备。切换为家长不能仅修改本地 `role`，必须重新认证/有有效监护人会话。共用平板时家长模式退出后清除敏感页面缓存。
- API 契约通过生成的类型共享，不共享后端 ORM。前端缓存包含用户/家庭/学生范围；切账号/撤销同意/解绑清除缓存及文件引用。
- 后端统一权限与数据模型。各端不是独立数据孤岛，但平台管理端不得直接连接数据库。

### UI 框架与原型落地决策（2026-10-25）

平台正式工程采用 Vue 3 + TypeScript + Vite + Element Plus，参考 Pure Admin / Vben Admin 的导航、筛选列表、表单和权限呈现方式，先组合必需组件。家庭正式工程仍采用 uni-app（Vue 3 + TypeScript），H5/微信 P0、原生 App P1；先验证跨端表单、弹层、拍照、上传和可访问性，再确定具体组件适配。

当前 [三端原型](prototype/README.md) 使用 Vue + Element Plus + Vant Web，提供统一品牌、中文组件、表格搜索分页、抽屉、校验表单和移动布局。Vant Web 与 Vant Weapp 是不同实现，不能把 Web 运行结果等同小程序验收。当前 JavaScript 原型后续需接入 TypeScript 类型、真实 API 状态、认证和权限；共享设计 token 与业务语义，按端实现交互适配。

设计规范、GitHub 证据、许可及替代方案见 [13 UI 框架调研](research/13-frontend-ui-framework-and-design-system.md)。19 个页面与需求/缺口映射见 [功能列表](小知功能列表.md)；原型不改变下文的正式交付要求。

### 正式平台身份客户端当前状态

`frontend/platform` 已实现独立平台身份：密码+图形验证码登录、本人会话、退出/退出全部、角色、只读账号与审计。令牌仅驻内存，含401/403、权限重验、到期清理、游标分页、错误重试及390px适配；正式数据授权由后端执行。详见[客户端计划](plans/2026-10-25-platform-web-client.md)。

这不是三端全业务完成：孩子/家长仍为演示原型，平台学校/学生家长/教材/模型治理以及账号邀请、角色分配、停用等正式页面与写入流程尚待开发。正式工作区与原型的品牌色还需统一评审，不能宣称所有设计token已经统一。

## 2. 页面树及主要状态

| 端/页面       | 主操作                     | 必须覆盖的状态                 |
| ---------- | ----------------------- | ----------------------- |
| 孩子：首页      | 今天课表、继续订正、到期复习、明日预习     | 未绑定、当天无课程、待确认结果、无网络     |
| 拍作业        | 拍照/相册、裁剪旋转、页排序、确认已尝试、上传 | 权限拒绝、过大、模糊、重复提交、单页重传    |
| 批改进度       | 展示排队/识别/检查、可离开稍后回来      | 超时、部分失败、取消、父母撤销、供应商不可用  |
| 逐题结果       | 原图高亮、结论文字、我的答案、分级提示     | 待确认≠做错、未答、题型不支持、图已删除    |
| 订正/复习      | 先作答再看反馈，查看历史努力记录        | 跳过不记完成、重复点击幂等、答案识别不清    |
| 预习卡        | 明日章节、目标、5～10分钟小任务       | 未选教材、进度未确认、调课导致旧卡失效     |
| 家长：首页/孩子切换 | 待核对、学习概况、快捷课表           | 无孩子、跨家庭切换、权限不足          |
| 提交记录/核对    | 按日期/科目筛选、图文对照、修正OCR/判题  | 版本冲突409、改判后重算、原图过期      |
| 错题库/复习计划   | 筛选、归档、周/月精选、P1打印        | 无错题、超过20题/20分钟、重复计划共用任务 |
| 周/月报告      | 计数、知识点、来源、计划入口          | 空周期不生成“进步”、数据更新中、样本不足   |
| 课表/教材设置    | 学期、节次、单双周、调课、版本/进度确认    | 冲突、放假、无授权内容、P1截图导入待确认   |
| 隐私/家庭/额度   | 邀请监护人、设备、导出、删除、消费记录     | 二次验证、撤回处理、额度不足、仅家长支付    |
| 平台后台       | 租户、教材、授权、模型、任务、成本、审计    | 默认无儿童内容；临时访问工单到期收回      |

P1追加书写反馈页与受限辅导会话；其 UI 必须标注“辅助建议”，不能伪装教师正式评分。孩子展示任务完成和具体努力反馈，不公开家庭或班级排名。

## 3. 上传与异步体验

1. 首次拍照前用一屏说明：只拍作业、避免姓名/人脸、清晰平整；不强制索取通讯录/位置/麦克风。
2. 一次1～9张，每张≤10MiB。客户端压缩是体验优化，服务端仍解码校验；保留足够字迹分辨率，压缩参数用真实手写评测决定，不盲目降至固定低清。
3. 本地保存不含原图的上传草稿ID和服务端对象ID；前台重试以幂等键恢复。首版不做自动后台无限上传或长期缓存儿童原图。
4. 上传失败保留成功页，只重传失败页。上传结束后202进入任务详情；用户离开不影响已接受任务。
5. 基础轮询按服务端建议起始3秒、随后5/10秒退避；前后台切换暂停/恢复，任务终态停止。切换孩子/账号后取消旧请求并丢弃迟到响应。
6. SSE只可作H5/App体验增强，不作为小程序或后台任务正确性依赖。推送订阅需单独授权，拒绝不影响核心功能。
7. 不能给模型等待动画假装固定百分比；展示真实阶段及“可以离开，结果稍后查看”。超过正常等待提示后可查询，不重复新建任务。

## 4. 跨平台能力矩阵

| 能力    | H5 P0                  | 微信小程序 P0                | Android/iOS P1              |
| ----- | ---------------------- | ----------------------- | --------------------------- |
| 登录    | 短信/受支持微信网页流程；不同环境区分    | 微信code服务端交换，家长同意后绑定     | App支持的登录渠道；账号关联需验证          |
| 拍照/相册 | 浏览器文件选择；微信内置与Safari专项测 | 官方相机/相册API；隐私声明和权限适配    | 系统权限；iOS受限相册/Android照片选择器测试 |
| 上传    | 直传、CORS、前台重试           | 域名白名单、真机HTTPS、大小/超时限制核实 | 前台可靠上传；后台能力如需另立需求           |
| 原图定位  | 统一归一化bbox，缩放后绘制        | 不依赖DOM；canvas与像素比实测     | 旋转、刘海安全区、缩放实测               |
| 通知    | 站内状态；不承诺浏览器后台推送        | 用户授权的订阅消息；不得滥发          | 系统推送单独接入与同意                 |
| 打印P1  | 服务端PDF→下载/系统打印         | 安全导出/转发文件流程，不承诺直接打印API  | 系统打印/分享，验证隐私留痕              |
| 删除/导出 | 家长二次验证                 | 同一服务端权限                 | 同一服务端权限及商店政策核验              |
| 更新    | Web发布                  | 平台提审/灰度                 | 商店提审，原生能力变更不靠热更新绕审核         |

实际目标：iOS Safari、Android Chrome、微信内置浏览器，至少各2类真机；小程序iOS/Android各2台；App低/中档Android与至少2代iPhone。第1周冻结最低系统/基础库版本和真实矩阵，以当期官方支持为准，而不是文档承诺所有机型。

## 5. 伙伴感与可访问性

品牌统一“小知 · Wizzy”，标语“每天学一点，进步看得见”。功能名用孩子听得懂的“拍作业、再试一次、明天学什么”，同时保留家长可查的题型/版本证据。

- 常用触控区域约44px以上；大字号、可读行距。正确/错误/待确认都有图标+文字，不只用红绿区分。
- 不用“你真笨/击败了多少同学”，不对未完成提醒制造羞耻。休息提醒默认20分钟，家长可管理，不用连胜奖励鼓励长时间使用。
- 明确“我是AI学习助手，可能看错”；不声称真人老师、不引导秘密对话或情感依赖。角色亲切不等于模拟亲密关系。
- 孩子先看到自己的作答与一层提示，完整参考答案仅在服务端策略允许的订正步骤/家长路径返回；不能把答案完整下载再靠CSS隐藏。
- 所有模型文本以受控Markdown/纯文本渲染，禁任意HTML/脚本/远程资源；公式渲染禁危险命令。

## 6. 前端验收与产物

交付页面清单/交互原型、路由权限表、平台适配代码、OpenAPI类型、真机报告、无障碍检查。E2E覆盖：配对→上传→离开重进→待确认核对→订正→到期复习→周报→删除。P0两平台分别验收，不能用H5通过替代小程序通过；App列为独立P1里程碑，不能在P0销售承诺已支持商店版本。
