## 一、先看结论

把需求拆成三个闭环，而不是三个孤立功能：

| 功能 | 本质 | 需要的新能力 | 可复用现有能力 |
|---|---|---|---|
| 英语单词听写 | 「读单词 → 学生写 → 判拼写」 | TTS 生成读音 | `activity_type='dictation'` + `reference_text` 的批改链路已存在 |
| 语文课文听写 | 「读课文/生字 → 学生写 → 判对错」 | TTS（多音字 SSML）+ 手写转写/比对 | 同上；`textbook_content` 已有分页课文正文 |
| 课程预习提醒与检查 | 「明日上什么课 → 提前提醒 → 是否预习、预习得怎么样」 | 定时提醒 + 推送 + 轻量检查 | `timetables.instances()` 已能算明日课表；`daily_homework` 已有 `item_type='preview'` |

**核心结论（推荐）**：

1. **听写判分不重做**，复用现有 `homework_grading.py` 里已实现的 `dictation` 批改类型（`SUBJECTS`、`activity_type='dictation'`、`reference_text`、`homework_results.py` 的 word/phrase 判分规则都已就位）。新做的是**「读音生成」**和**「词表/课文内容组织」**。
2. **读音生成 P0 用服务端 TTS 预生成并缓存**：`edge-tts`（免费、中英音色好）做 MVP/试点，生成 mp3 存入现有对象存储，按 `(文本, 音色, 语速, SSML)` 哈希去重缓存。生产/商用**必须切换为有授权可合同的供应商**（讯飞/阿里云/腾讯云，或官方 Azure），并把 edge-tts 的非官方接口性质作为已知风险处理。
3. **朗读/口语（"说"的部分）P0 可后置**：听写先只做"听→写"；需要"读单词/读课文打发音分"时，优先接**讯飞语音评测**（K12 口语评测专用）或自建 `FunASR`/`sherpa-onnx`。不要为了"说"而在 MVP 引入本地 GPU 语音模型。
4. **预习提醒用「课表派生 + Celery beat 扫描 + 微信订阅消息」**：`timetables.instances()` 已产出明日课程实例，晚上定时把明日课程生成 `item_type='preview'` 的待办并推送；检查用"家长确认 / 自报朗读 + 可选 1~3 道 LLM 生成的理解题"两级，不搞复杂评分。

## 四、技术选型建议

### 4.1 TTS 选型对比

| 维度 | edge-tts（P0） | 讯飞/阿里云/腾讯云（生产） | Azure Speech（生产备选） | Piper / sherpa-onnx（离线） | CosyVoice（自建） |
|---|---|---|---|---|---|
| 中文自然度 | 好 | 很好 | 好 | 一般 | 很好 |
| 英文自然度 | 好 | 好 | 很好 | 中 | 好 |
| 成本 | 免费（非官方） | 按字符付费 | 免费额度+付费 | 免费 | 自建算力 |
| 多音字 | 支持 SSML 音标 | 支持 SSML/拼音 | 支持 SSML | 弱 | 需自处理 |
| 合规/合同 | ❌ 无合同、非官方 | ✅ | ✅ | ✅（本地） | ✅（本地） |
| 部署 | 联网调用 | SaaS | SaaS | 端侧/服务器 | 自建（重） |

**推荐**：

- **P0/MVP/试点**：服务端 `edge-tts` 预生成 mp3 → 存对象存储 → 客户端 `uni.createInnerAudioContext()` 播放。理由：零成本、中英音色好、接口简单，能快速验证产品闭环。
- **生产/商用**：换**讯飞开放平台 TTS**（大陆 K12 主流、中文最优、可合同）或**阿里云/腾讯云**；若走海外，用**官方 Azure Speech**。同一套抽象（`TTSEngine` 接口）把 edge-tts 和云 TTS 都实现，切换只换配置。
- **离线兜底（P1/P2）**：App 内离线 `sherpa-onnx`（中英都能离线读，适合断网/校园场景），服务器自建 `CosyVoice` 仅当要音色定制/克隆时再评估。

### 4.2 ASR / 语音评测选型（仅当启用"说"）

- **发音打分（首选）**：讯飞语音评测（音素级评分，K12 口语场景成熟）。
- **自建转写**：`FunASR`（服务器，中文最优）+ 确定性比对；端侧离线用 `sherpa-onnx`。
- 均**P1 起**，MVP 不做。

### 4.3 判分选型

- **首选**：复用 `homework_grading.py` 现有 `dictation` 链路（`activity_type='dictation'` + `reference_text` = 词表/课文标准文本），LLM 视觉模型一次完成"手写识别 + 对错 + 订正"。
- **可选优化**：`PaddleOCR` 手写体确定性转写 → 字符级/拼音级比对，把"确定对"的项直接放行、只把模糊项送 LLM，降低成本。

## 五、功能方案设计

### 5.1 英语单词听写

**闭环**：选词表 → 生成/取读音 → 逐词播放（可选中文释义/例句）→ 学生书写/输入 → 上传判分 → 错词入错题本。

**模式**（二选一或可切换）：
- 听写模式：播放英文读音（可加"写单词/写中文释义"两种答题要求）。
- 看义写词模式：显示中文释义，学生写英文单词。

**流程**：
1. 词表来源：教材生词（`textbook_content` 章节内词表，若已有）→ 家长/老师录入或导入 → 现有错题本高频错词。
2. 服务端 `POST /dictation/audio` 批量合成：按词、按 `(text, voice, rate, ssml)` 哈希缓存 mp3；返回 media URL。
3. 客户端顺序播放（`uni.createInnerAudioContext`），可设置"每词读几遍、间隔几秒、是否播中文释义"。
4. 学生把听写结果写在纸上拍照（复用现有上传/质量检查），或前端手写/键盘输入。
5. 提交时 `activity_type='dictation'`、`reference_text='词表: word1, word2, ...'`；批改 worker 走现有链路，逐词判 `correct/incorrect/unanswered/unclear`。
6. 错词自动进入错题本（`mistake_bank.sync_submission` 已接），供 1/3/7/14 复习与下次听写。

**要点**：英文单词听写判分**可以是确定性的**（拼写比对），但保留 LLM 判分以处理手写字迹与"weather/whether"这类同音歧义（现有规则已明确不得乱纠）。可先做"键盘输入版"把拼写比对做成纯确定性、零 LLM 成本。

### 5.2 语文课文听写

**闭环**：选课文/生字 → 逐字逐句播放（多音字用 SSML）→ 学生书写 → 上传判分 → 错字入错题本。

**与英语的关键差异**：
1. **多音字**：必须按字配 SSML 音标（参考 cn-dictation 的 `<phoneme alphabet="sapi" ph="...">`），或由 TTS 供应商的"拼音标注"接口处理。这是语文听写最大的正确性风险。
2. **判分容错**：中文听写要处理**同音字**（"的/得/地"）、**形近字**、"漏字/多字/语序"。字符级精确比对会误伤同音字，需要**拼音级模糊匹配** + LLM 判断。
3. **内容授权**：课文正文必须来自已授权的 `textbook_content`（`verified=true`），不能自动抓取网络教材。

**流程**：
1. 选课文：从 `textbook_content` 取章节正文（分页 `text`），或选"生字表"逐字听写。
2. 服务端对逐句/逐字生成 TTS（SSML 多音字音标），缓存 mp3。
3. 学生听写后上传图片，`reference_text` = 该句/该字标准文本。
4. 判分：LLM 视觉批改（复用现有），规则放宽为"拼音正确 + 字形正确"才判对，同音异形单独标 `unclear` 供家长确认；错字入错题本。
5. 家长可看"哪些字常错、同音字混用清单"（复用现有汇总/报告）。

### 5.3 课程预习提醒与检查

**闭环**：明日课表 → 生成预习待办 → 定时提醒 → 学生预习 → 轻量检查/确认 → 次日听写/课堂闭环。

**流程**：
1. **派生**：每天定时（如 20:00）用 `timetables.instances(term, tomorrow)` 拿明日课程实例（`subject`/`period`/`start_time`）。
2. **生成预习待办**：为每门明日课程生成 `daily_homework` 的 `item_type='preview'` 项，`due_at = 明日首课时间`，`locator` 绑定教材章节（`book_alias/lesson/pages`）。若已有同课程预习项则不重复生成（幂等）。
3. **提醒**：Celery beat 定时任务扫描"未完成且临近 due_at 的 preview 项"，触发推送。
4. **推送**：微信小程序用**订阅消息**（一次性订阅，需在设置提醒时 `wx.requestSubscribeMessage` 拿授权）；H5 用浏览器通知 + 站内红点；App 用厂商推送。MVP 先做"站内提醒 + 微信订阅消息"，不做全量厂商通道。
5. **检查（两级，从轻到重）**：
   - L1 自报/家长确认：`preview` 项 `completed`（复用现有 `WorkState`）。
   - L2 轻量理解题：用 LLM 从教材章节生成 1~3 道选择题，学生答完即算"已预习"，答错仅提示回到原文，不计分不入错题本。
   - L3 朗读打卡（可选，P1）：接 ASR/语音评测，"把课文读一遍"检查。

**要点**：检查不追求"预习质量评分"，避免误伤；核心是"提醒到位 + 有轻量动作 + 次日课堂/听写形成闭环"。

## 六、数据模型与 API 扩展（建议）

> 沿用现有 `run(db, 'SELECT public.fn(...)')` 的存储函数模式与 RLS 多租户约束。

### 6.1 新表

```sql
-- 听写任务（一份听写 = 一组条目 + 每条目标文本 + 读音）
dictation_sets(
  id uuid PK, tenant_id, student_id, deletion_epoch,
  subject text,            -- english / chinese
  title text,              -- 如 "Unit 3 单词" / "第5课 课文"
  source_kind text,        -- textbook / manual / mistake_bank
  book_alias text, lesson text, pages jsonb,   -- 来源定位
  item_style text,         -- word / phrase / sentence / hanzi
  play_options jsonb,      -- 每项读几遍、间隔、是否播释义、音色、语速
  created_at, updated_at
);

dictation_set_items(
  id uuid PK, set_id FK, position int,
  target_text text,        -- 标准文本（判分依据）
  prompt_text text,        -- 播放/展示文本（可为中文释义或提示）
  ssml text,               -- 多音字音标覆盖（语文）
  audio_key text           -- 已合成语音的对象存储 key（可空，懒生成）
);

-- 预习提醒（也可直接复用 daily_homework_items 的 preview 类型 + 新增提醒字段）
preview_reminders(
  id uuid PK, tenant_id, student_id,
  item_id uuid FK,          -- 指向 daily_homework 的 preview 项
  schedule jsonb,           -- 提醒规则：{at: "20:00", before_minutes: 30}
  channel text,             -- in_app / wechat_subscribe / push
  last_sent_at timestamptz, next_sent_at timestamptz,
  enabled bool
);
```

> 说明：`daily_homework` 已能表达 `preview` 项（`item_type='preview'` + `due_at`），故预习提醒的最小实现甚至无需新表，只需在 `daily_homework_items` 上新增"提醒开关/时间"即可；新表用于存放多通道推送的投递状态。

### 6.2 新路由（前缀沿用 `/api/v1`）

```
POST   /students/{student_id}/dictation/sets            # 建听写任务
GET    /students/{student_id}/dictation/sets            # 列表
GET    /dictation/sets/{set_id}                         # 详情（含条目与 audio URL）
POST   /dictation/sets/{set_id}/audio                   # 批量生成/取读音（幂等、返回 media URL）
POST   /dictation/sets/{set_id}/submit                  # 复用 submissions：activity_type=dictation
GET    /timetables/{term_id}/preview-plan?date=...      # 明日预习清单（派生，只读）
POST   /students/{student_id}/preview-reminders         # 设置提醒（返回订阅消息授权参数）
```

### 6.3 关键复用

- 提交/批改：直接走 `submissions` + `homework_grading` worker，`activity_type='dictation'`、`reference_text = '\n'.join(item.target_text)`。
- 音频：复用 `media.py` / 对象存储，`audio_key` 走私有访问（与作业图片同等的 `storage_root` 路径约束与私有化处理）。
- 派生明日预习：复用 `timetables.instances()`（`backend/src/wizzy/timetables.py`），不另写课表展开逻辑。

## 七、前端实现要点（uni-app）

- **音频播放**：`uni.createInnerAudioContext()`（H5 与微信小程序通用）。预加载下一个词，减少停顿；支持"再读一遍""慢速"。
- **听写作答**：MVP 优先做**键盘/手写板输入**（拼写/选字），把判分做成确定性；拍照手写判分作为第二阶段（复用现有拍照上传）。
- **订阅消息**：小程序端在"开启提醒"时调用 `wx.requestSubscribeMessage` 拿一次性授权；服务端按 `preview_reminders.schedule` 用订阅消息模板发送。H5 降级为站内红点 + 浏览器通知。
- **多端共享**：新页面走现有 `frontend/family/src` 的 Vue 组件化，与 `DailyHomeworkPanel`/`HomeworkPageResult` 同层，避免新增平台特例。

## 八、分阶段实施建议

按现有 2 后端 + 2 前端 + 1 QA 估算，不影响既有 12 周主计划的前提下，作为**P1 增量**排期：

| 阶段 | 内容 | 增量工时（人日） | 交付物 |
|---|---|---|---|
| P0（2~3 周） | edge-tts 服务端合成+缓存；英语单词听写（键盘输入+确定性判分）；语文生字/课文听写（复用 LLM dictation 判分，SSML 多音字）；明日预习清单派生 + 站内提醒 | 后端 8~10 / 前端 8~10 / QA 4 | 三端可用的听写 + 预习提醒 MVP，附真实样本评测 |
| P1（按余量） | 拍照手写判分接入；朗读/口语打卡（讯飞语音评测或 FunASR）；微信订阅消息推送；错题 → 听写联动 | 后端 6~8 / 前端 6~8 / QA 4 | "听→写→判→订正→复习"完整闭环 |

**验收基线（与现有文档口径一致）**：
- 听写判分安全：单词/生字白名单"确定对"自动放行准确率目标 ≥99%，同音字/字迹不清一律 `unclear` 待确认，不误判正确。
- 提醒可靠：同一预习项不重复提醒、不重复生成；订阅消息失败可重试且不影响业务。
- 成本：TTS 预生成命中缓存后，重复听写零语音成本；单次新词表合成成本按字符数核算并设上限（沿用 `09` 的预算口径）。
- 合规：TTS/ASR 供应商、教材课文、订阅消息模板三者的授权与隐私评审在产品化前签字（沿用 `08`）。

## 九、风险与合规

1. **edge-tts 非官方接口**：无合同、许可 NOASSERTION、接口可能变更或封禁。仅用于 MVP/试点；商用前换有合同供应商，且不把 edge-tts 写入对外承诺的 SLA。
2. **教材课文授权**：语文听写的课文/生字正文必须来自已授权且 `verified=true` 的 `textbook_content`，不得自动抓取网络教材；授权到期要有内容冻结/下线机制（沿用 `08`）。
3. **未成年人数据与语音**：学生语音、听写音频属于未成年人个人信息，默认私有存储、最小留存、可删除可导出；朗读打卡录音默认不长期保存，仅用于即时评测。
4. **多音字/同音字误判**：语文听写最大的正确性风险；多音字靠 SSML 音标与评测集覆盖，同音字判分一律"待家长确认"而非硬判错。
5. **推送合规**：微信订阅消息需用户逐次/逐模板授权，不得替代为强制；提醒频率可关、可调，避免打扰。
6. **语音评测供应商**：发音打分模型需用真实小学生样本做评测集，不把供应商自报准确率当作产品准确率（沿用 `04` 原则）。
