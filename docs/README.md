> 每天学一点，进步看得见。
>
> 版本：评审稿 v1.2｜编制及联网核验日期：2026-10-25（Asia/Shanghai）
> 状态：三端交互原型与后端首批能力已提供；PostgreSQL 迁移及隔离集成测试已运行。平台身份只读正式 Web 切片已联调，家庭正式客户端、真实 AI 与其余完整业务仍待开发，不构成已验证的准确率承诺。

## 一、先看结论

1. **定位**：面向小学生的学习伙伴，围绕“完成作业 → 上传检查 → 发现问题 → 自主订正 → 周/月复习 → 明日预习”形成闭环。家长看过程与支持方法，不只看分数。
2. **三个业务端**：孩子学习端、家长管理端、系统平台管理端。孩子/家长采用 uni-app（Vue 3 + TypeScript）多端工程；平台管理采用 Vue 3 + TypeScript + Vite + Element Plus 独立 Web 管理台。微信小程序、H5 先上线，Android/iOS 随后交付，不把“跨端”当成无需真机适配。
3. **后端优先方案**：Python FastAPI 模块化单体，PostgreSQL、Redis、Celery、私有对象存储；API 与异步 Worker 独立进程部署、共享业务代码。首版不引入 Go、微服务、Kubernetes、向量数据库或自建 GPU 集群。
4. **AI 方案**：云 OCR/视觉结构化 + 确定性规则 + 视觉模型判题 + 高风险复核 + 家长纠正。Qwen 系列先做主供应商候选；DeepSeek 当前视觉模型作为独立对照候选；豆包及专用教育批改 API 进入比测清单。最终采购由真实小学作业评测、地域及合同条件决定。
5. **准确性原则**：不确定就标“待确认”；把“识别结果”“判题结果”“人工确认”分开。模型自报置信度和两个模型投票都不是准确性证明。
6. **租户**：首版一个家庭是一个租户，支持多孩子、多监护人；平台共用软件不等于家庭互看数据。机构租户后置，禁止凭空开放机构管理员查看儿童作业。
7. **范围**：MVP 自动判题聚焦小学数学封闭型题；语文、英语基础客观题受控开放，主观题仅辅助评价。课程表、基础课本目录、预习、错题及周/月复习贯穿三端。
8. **排期**：按 2 后端 + 2 前端 + 1 QA + 兼职教研/产品/运维估算，12 周优先完成 P0 技术交付和受控试点；商用另需独立签字。App 与其他 P1 按余量另验收，外部备案、教材授权、应用审核不承诺在此期限内完成。

以上是设计决策，不是所引项目已经提供整套能力。事实依据与建议的区别见研究文档。

## 三、使用方法与完成标准

- 先确认 `01` 的假设；未确认项采用保守默认值推进，不擅自扩大范围。
- 第 1～2 周优先验证真实作业准确率和跨端拍照；不是先把所有页面画完再判断 AI 是否可用。
- 开发票据引用需求编号，代码 PR 必须关联验收用例；每次模型/Prompt/题目切分变更都生成评测版本。
- 功能完成、质量达标、合规通过分别签字；三者不能互相替代。
- 本目录包含方案 Markdown 和独立 Vue 组件化交互原型；正式 FastAPI 源码在 `backend/src/wizzy`，迁移在 `backend/migrations`。家庭授权、私有图片、提交与额度预占已有真实 PostgreSQL 集成测试；架构中的其余接口/SQL 仍是规划或示例，具体状态见 14。原型仍使用演示数据；独立正式平台身份客户端在 `frontend/platform`，仅接0015身份七接口，启动与测试见[本地开发](local-development.md)。
