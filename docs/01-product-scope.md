# 01 产品范围与关键决策

## 1. 产品定义

**小知 · Wizzy** 是孩子能直接叫出名字的学习伙伴，不是“全自动正确答案机”。核心价值是让孩子自己完成、发现、订正，让家长了解学习过程、减少机械整理负担。

- 孩子：“小知，帮我检查已经做完的作业”“明天要准备什么？”
- 家长：“本周哪些问题反复出现？哪些结果需要我确认？怎么辅导而不直接告诉答案？”
- 平台：“不同家庭数据隔离是否有效？教材授权到期了吗？哪类题误判率高？费用是否异常？”

用户原文中的“写字工整如与的打分”暂解释为**写字工整度评分与改进建议**，不是笔迹身份识别、书法等级考试或心理诊断。

## 2. 规划假设与可调整项

| 项目       | 当前默认                                 | 若不同的影响             |
| -------- | ------------------------------------ | ------------------ |
| 市场       | 中国大陆、简体中文、Asia/Shanghai              | 海外部署需重新核验法规、供应商及费用 |
| 年龄       | 小学 1～6 年级；数据字典允许扩展初高中                | 扩学段必须另建题型和评测集      |
| 付费方/账号主权 | 家长；儿童无需手机号                           | 学校统一管理需新增授权及组织边界   |
| 租户       | 家庭租户，多家庭共用 SaaS                      | 机构租户为 P2，不混入 MVP   |
| 教材       | 首批选一个合法可用的版本/年级进行试点                  | 不预设已获得人教版等教材电子版权   |
| 规模       | 试点 50～100 家庭；第一商业目标 1,000 活跃学生       | 此处为容量假设，不是已获得用户    |
| 输入       | 图片；每份作业 1～9 张，每张最多 10 MiB            | PDF/扫描仪批量上传 P2     |
| 平台       | H5、微信小程序、Android、iOS                 | 其他小程序/鸿蒙按实际需求后置    |
| 首发分发     | 小程序 + H5；App 在第 9～12 周按余量验证候选包，验收可顺延 | 商店审核时长单列           |
| 教师角色     | 首版没有教师端                              | 不把家长审核等同专业教师评分     |

## 3. 业务域与版本策略

### MVP / P0（第 1～8 周形成闭环）

- 家庭、监护人邀请、多孩子、儿童受限登录、监护人同意与撤销。
- 拍照/相册上传、质量检查、旋转裁剪、OCR/题目切分、数学封闭题批改、待确认、家长纠错。
- 自动/手动错题归档、订正、原题复习、基础 1/3/7/14 日调度及周/月复习计划。
- 课程表手动维护、周次与临时调课；教材目录版本、章节绑定；次日预习清单。
- 家长提交历史、错题筛选、周/月结构化汇总、来源可追溯辅导。
- 平台租户、教材元数据及授权、模型配置、用量、审计、失败任务管理。
- 隔离、删除、导出、内容安全和成本限制从首版实现，不后补。

### P1（第 9～12 周起按余量分项推进，其余另排）

- Android/iOS 分发准备及真机验收；H5/小程序功能完善。
- 语文/英语基础客观题扩大覆盖；作文字词建议、应用题过程辅助反馈。
- 工整度多维辅助评分；家长引导式辅导；受控题目变式；可打印复习卷及结果回填。
- 课表截图识别预填与人工确认、授权教材片段检索。

### P2 / 明确不在首版

机构租户、教师端、学校 SIS、直播/真人付费培训、社区排行榜、社交聊天、广告、儿童自主支付、全学科全题型自动评分、完整手写笔画诊断、自训大模型、离线 OCR、端侧完整 AI、自动采集网络教材。

## 4. 成功指标（规划目标，不是当前数据）

| 维度   | 首期目标                      | 如何验证                      |
| ---- | ------------------------- | ------------------------- |
| 完成闭环 | 试点中 ≥70% 首次有效上传家庭完成一次结果查看 | 只统计已同意采集的最小事件             |
| 自主订正 | 错题中 7 日内有一次订正记录的比例 ≥50%   | 不是必须做对，更不是学习效果因果证明        |
| 批改安全 | 自动放行题准确率目标 ≥99%，重点看误判正确   | 见 `04` 分层与置信区间；不能只报告总体准确率 |
| 覆盖   | 白名单题型自动放行覆盖目标 ≥60%        | 分母含真实受理的不可判定题             |
| 服务   | 单页清晰标准作业完整结果 P95 ≤90 秒    | 上传完成起算，包含排队；长作业另报         |
| 成本   | 标准任务 AI 均摊初始目标 ≤0.10 元/页  | 独立核算辅导、报告、人工及基础设施         |
| 可解释  | 每个最终判定可追踪至图片、证据、模型/规则版本   | 抽样 100 条，覆盖重跑与人工改判        |

## 5. 关键决策 ADR 摘要

| 编号     | 决定                | 原因与代价                         |
| ------ | ----------------- | ----------------------------- |
| ADR-01 | FastAPI 模块化单体     | 减少 Python AI 与业务的语言切换；需严管阻塞任务 |
| ADR-02 | 图片原件与 OCR 文本双轨保存  | 可以复核、修正 OCR；增加存储和隐私责任         |
| ADR-03 | tenant=家庭         | 多家庭隔离清晰；机构协作后续单独设计            |
| ADR-04 | 白名单题型自动判，其他辅助/待确认 | 首版可信比全量覆盖重要；存在人工确认负担          |
| ADR-05 | 多端共享源码，孩子/家长逻辑分区  | 节约研发；必须防角色切换泄露家长数据            |
| ADR-06 | 规则优先、模型可替换、采购先评测  | 降幻觉与供应商锁定；仍需维护评测与适配           |
| ADR-07 | 不将家长纠错直接写全局标准答案   | 防污染其他家庭；教研审核后才能成为共享内容         |

## 6. 必须由产品负责人确认

首发渠道与运营主体、试点年级/教材、每月预算、人员配置、是否收费、App 上线时间、主观题边界、教材授权来源、家长复核可接受比例、原图保存期。未确认前采用上表默认；**未经监护人同意不得开展真实儿童数据试点，未经上线合规审查不得公测经营**。
